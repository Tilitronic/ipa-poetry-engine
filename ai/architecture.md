Ось комплексна архітектура вашого проєкту. Вона побудована на принципі **"Фонетика як Лінійна Алгебра"**.

Ми розділимо систему на шари (Layers), щоб вона була швидкою (Rust), портативною (Python/Web) та математично точною.

---

## 1. Технологічний стек (Tech Stack)

- **Ядро (Core Engine):** Rust 🦀 (забезпечує мікросекундну швидкість для роботи з матрицями та пам'яттю).
- **Математика:** `ndarray` (Rust-аналог NumPy для швидких векторних операцій та обчислення відстаней).
- **Серіалізація:** `serde`, `serde_json` (для швидкого одноразового парсингу вашого `phonemes.json`).
- **Інтерфейси (Bindings):**
- `PyO3` (щоб скомпілювати Rust-код як звичайний модуль Python `import phonetics_engine`).
- `wasm-bindgen` (щоб скомпілювати ядро для роботи прямо в браузері через JavaScript/TypeScript).

### 3.1. База знань (Singleton)

### 3.2. Фонетичний Токен

Представляє один звук або паузу у вірші.

```rust
pub enum TokenType {
    Phoneme,
    WordBoundary, // Пробіл
    LineBreak,    // Кінець рядка (\n)
}

pub struct PhoneticToken {
    pub symbol: String,         // напр. "t͡s"
    pub t_type: TokenType,
    pub features: Array1<f32>,  // Вектор ознак (довжина 24)
    pub weight: f32,            // Вага (наголошений голосний = 1.5, ненаголошений = 0.8, пауза = 0.0)
}

```

### 3.3. Текст як Матриця (PhoneticStream)


## 4. Ключові Алгоритми (Logic Layer)

### Алгоритм 1: Токенізація (Longest Prefix Match)

Оскільки у вас є символи типу `ɡʲː` (3 символи Unicode), ви не можете читати по одній літері.

- **Як працює:** Беремо рядок, дивимося на 4 символи вперед. Чи є такий ключ у `FeatureRegistry`? Якщо ні, дивимося на 3. Якщо ні, на 2. Якщо так — відкушуємо, створюємо `PhoneticToken`, йдемо далі.
- _Результат:_ Рядок "d͡ʒmʲilʲ" безпомилково розбивається на `[d͡ʒ]`, `[mʲ]`, `[i]`, `[lʲ]`.

### Алгоритм 2: Метрика схожості (Cosine Similarity)

Для порівняння двох звуків (або двох складів).

- **Як працює:** Рахує кут між двома багатовимірними векторами.
- _Формула:_ $cos(\theta) = \frac{A \cdot B}{||A|| \times ||B||}$
- _Результат:_ Дає число від -1 до 1. (Напр., `p` та `b` дадуть 0.9, а `p` та `a` дадуть -0.4).

### Алгоритм 3: Пошук Алітерацій (Sliding Window Density)

Для знаходження звукових скупчень ("плям") всередині тексту.

- **Як працює:** Беремо "вікно" розміром у 10 звуків. Рахуємо суму всіх векторів у цьому вікні. Пересуваємо вікно на 1 крок вправо, рахуємо знову.
- _Результат:_ Якщо в якомусь вікні параметр `strident` (шиплячі/свистячі) досягає піку — ми знайшли алітераційну групу.

### Алгоритм 4: Пошук неточних та складених рим (DTW - Dynamic Time Warping)

Найкрутіша фіча вашого проєкту. Класичні алгоритми "ламаються", коли довжина слів різна (паровоз / пара воз).

- **Як працює:** DTW розтягує або стискає послідовності векторів у часі, щоб знайти найкраще математичне суміщення двох матриць, ігноруючи токени `WordBoundary`.
- _Результат:_ Програма розуміє, що два слова римуються з одним, бо їхні загальні фонетичні траєкторії збігаються.

## 5. Пайплайн даних (Data Flow)

Як дані йдуть від користувача до результату:

1. **G2P (Grapheme-to-Phoneme):** Користувач вводить текст "башук капуш". _Зовнішня система (напр., Python-скрипт або словник)_ перетворює це на IPA: `b a ʃ u k # k a p u ʃ`.
2. **Engine (Input):** Цей IPA рядок передається у ваш Rust-модуль.
3. **Engine (Parsing):** `tokenizer.rs` перетворює рядок на масив `PhoneticToken` + додає вектори з `FeatureRegistry`.
4. **Engine (Matrix):** `matrix.rs` склеює вектори в одну велику 2D матрицю.
5. **Engine (Analysis):** Викликаються алгоритми (DTW для рими, Sliding Window для алітерацій).
6. **Output:** Rust повертає JSON назад у Web/Python із координатами знайдених зв'язків.

Наприклад:

```json
{
  "rhymes": [
    {
      "type": "imperfect",
      "indices_A": [0, 1, 2, 3, 4],
      "indices_B": [6, 7, 8, 9, 10],
      "score": 0.82
    }
  ]
}
```
